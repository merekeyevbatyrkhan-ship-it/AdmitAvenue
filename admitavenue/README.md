# AdmitAvenue

Персональный маршрут поступления. LOCUS Startup Hackathon 2026, кейс LOCUSCASE2.

## Состояние: v0.5, разработка

Реализованы адаптивная главная, плавный фон и анимации с reduced motion, RU/KK/EN, анкета из шести разделов, исследование интересов, итог профиля и JSON-экспорт. Экзамены различают «не сдавал», «запланирован» и «сдан»; отсутствие результата не становится нулём. Профориентация использует правила, а не AI и не вероятности поступления.

Добавлены Supabase Auth (email/пароль, подтверждение email, восстановление пароля) и чтение/сохранение анкеты в PostgreSQL. Гостевой черновик автоматически сохраняется локально. После входа пользователь явно выбирает анкету из аккаунта или перенос гостевого черновика. Облачные изменения сохраняются кнопкой «Сохранить в аккаунт»; сайт предупреждает перед уходом с несохранёнными изменениями. Облачный профиль не записывается в гостевое хранилище. При выходе восстанавливается прежний гостевой черновик.

Работает личный кабинет: обзор профиля, подбор с объяснениями, поиск и фильтры, избранное, сравнение 2–3 программ, выбор цели и персональный план с датами, отметками выполнения и ближайшим действием. В каталоге 22 программы из четырёх университетов Казахстана, Венгрии и Италии. Данные собраны вручную с официальных сайтов, со ссылками и датой проверки. Подбор использует правила, не AI и не оценку вероятности зачисления. Неизвестные цены и сроки явно обозначены. Подробности — [источники каталога](docs/catalog-sources.md).

Избранное, сравнение, цель и прогресс хранятся внутри анкеты (`journey`) и проходят тот же механизм локального/облачного сохранения. Новая SQL-миграция не нужна. При изменении значимых ответов связанные задачи пересоздаются; остальные отметки остаются. Даты задач — личные сроки пользователя, не официальные дедлайны.

Работает мини-чат OpenAI на главной и в кабинете: профориентация, вопросы и разбор анкеты по кнопке. Чат использует локальный каталог с датой проверки; выбор из живой таблицы Supabase остаётся незавершённым этапом. Каталог пока ограничен; полного поиска олимпиад и стипендий нет. Логотип A временный. Публичный деплой и проверка реальных аккаунтов остаются отдельными шагами.

## Запуск

Node.js 22+, pnpm (lockfile — pnpm-lock.yaml).

```sh
pnpm install --frozen-lockfile
```

Скопировать .env.example в .env и указать URL проекта и publishable key. В текущем локальном каталоге они уже настроены; .env исключён из Git.

```sh
pnpm start
```

Открыть http://127.0.0.1:4173. Команда собирает локальный браузерный SDK Supabase через esbuild и запускает сервер. Без настроек Supabase доступен гостевой режим. Это локальная разработка, не публичный деплой. Сервер слушает только loopback.

```sh
pnpm run check
pnpm test
```

## Настройка Supabase

Миграция supabase/migrations/202609180001_applicant_profiles.sql в проекте команды уже выполнена пользователем; повторно запускать её не нужно. Для нового проекта выполнить один раз, затем supabase/verify.sql.

В Authentication → URL Configuration → Redirect URLs добавить точный URL http://127.0.0.1:4173/profile.html. При работе через localhost добавить также http://localhost:4173/profile.html. Site URL при локальной разработке можно задать http://127.0.0.1:4173; после публикации заменить на публичный адрес сайта и добавить его /profile.html в разрешённые возвраты. Подтверждение email оставляем включённым. Локальная ссылка из письма открывается на том же компьютере, где работает сервер.

Настройки возврата и доставку писем в текущем проекте ещё нужно проверить в панели владельца. Доступность регистрации сама по себе не доказывает доставку email. Для публичного запуска проверить SMTP и ограничения отправки по документации Supabase.

## Архитектура

- public/profile-core.js: модель анкеты, нормализация, валидация, правила интересов.
- public/profile.js: анкета, язык, гостевое сохранение и просмотр результата.
- public/programs.js: каталог с источниками, годом стоимости и неизвестными значениями.
- public/journey-core.js: правила подбора, ограничения бюджета, зависимости задач и расчёт прогресса.
- public/journey-ui.js и journey.css: кабинет, каталог, сравнение, план и адаптивное оформление.
- public/account.js: формы Auth, выбор черновика, облачное сохранение, смена пользователя и ошибки.
- public/cloud-store.js: явные INSERT/UPDATE в admit_profiles и проверка revision.
- config.mjs и /api/config: только два публичных параметра. Пароль БД, service role и AI API ключ не передаются браузеру.
- server.mjs: файлы из public, публичная конфигурация и CSP с одним разрешённым Supabase origin.
- supabase/: схема и проверки. Одна строка JSONB на пользователя; паролями управляет Supabase Auth.

Используются официальный @supabase/supabase-js, dotenv и esbuild. Для тестов DOM — happy-dom. Сессия Auth хранится браузером; на общем устройстве нужно выходить из аккаунта. Гостевой черновик доступен другим пользователям того же браузера до очистки.

## Мини-чат OpenAI

В `.env` задать `AI_API_KEY` (или `OPENAI_API_KEY`) и `AI_MODEL=gpt-4o-mini`, затем перезапустить `pnpm start`. Кнопка «Спросить AI» справа внизу есть на главной, в анкете и кабинете. В анкете доступна кнопка «Разобрать мою анкету»; она явно включает передачу нормализованной анкеты. Имя, идентификаторы аккаунта и ссылки на доказательства исключаются. Свободный текст пользователь отправляет по своему выбору.

`POST /api/chat` вызывает OpenAI Chat Completions только на сервере, с `store:false`. История последних пяти пар сообщений передаётся с новым вопросом; после перезагрузки или смены аккаунта/языка история удаляется из памяти страницы. На сервере переписка не сохраняется. Вывод отображается безопасным текстом. Есть остановка, повтор, тайм-аут и сообщения о лимите/неверном ключе.

Ограничения: 3 000 символов на сообщение, 30 запросов с IP в час, 300 в сутки на процесс, до двух одновременных запросов. Эти лимиты сбрасываются при рестарте и не заменяют общую квоту для нескольких серверов. При публичном размещении нужен Node-сервер и `APP_ORIGIN` с точным HTTPS-доменом; секрет хранится в настройках сервера, не в Git или браузере.

Таблица программ Supabase этой работой не создана; подготовленная миграция `202609180002_program_catalog.sql` требует отдельного применения.
